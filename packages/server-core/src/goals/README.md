# Native Goals host wiring

The work in this module does not start a timer, connect a model, or create a session by itself. Without the host runtime, `start`/`resume`/`verify` persist an explicit `blocked` reason, not fabricated execution.

1. Configure `configureGoalRuntime({ createOwner, createVerifier, wakeSession, cancelSession })` before admitting Goals actions. Import this and `getGoalService` from `@craft-agent/server-core/handlers/rpc` (or directly from `service.ts` inside server-core). `createOwner` and `createVerifier` create **idle** sessions in the goal's workspace. The verifier must be new, unbranched and independent; never reuse the owner identity or an earlier verifier. Use the host's scoped Goal tool policy without goal-authored permissions or sources. The adapter must check scope and current permission mode again on every wake of an existing session.
2. Use `getGoalService(workspace.rootPath).forSession(actualSessionId)` in the trusted session-tool registry, never a session ID from tool arguments. The returned `get(id)` reads the goal and revision for a bound actor. `progress(id, revision, message)`, `ask(id, revision, question)`, `evidence(id, revision, name, content)`, and `requestVerification(id, revision)` are phase-checked. `verdict(id, revision, results, message)` is accepted only from the distinct assigned verifier. Every result has `id`, `status`, a nonempty workspace-relative `evidence/<filename>` file, and optional `note`. Do not register `userAction` or unrestricted filesystem/control-plane writes as agent tools. Goal prompts and Markdown are untrusted data, not authority.
3. Wire `wakeSession(goal, sessionId, message, signal)` to **admission**, not completion of a model turn. Honor the abort signal before and across async admission; `cancelSession(goal, sessionId)` must stop work (including child work) for a human pause/stop. A failed cancel is recorded as unconfirmed. Bind wake session validation to the specific workspace and actor; identify the workspace from trusted configuration using `goal.folderPath`, not a client-supplied path.
4. Run `recoverInterrupted()` for each known workspace before enabling the host's Goals runner. It blocks previously running goals rather than resuming them blindly. Run `await service.tick()` from a bounded host-owned scheduler while the host is running (and guard overlap/error handling). `nextWakeAt` is eligibility, not evidence a wake ran; nothing runs with the host closed. The service reserves budget before attempting runtime effects and intentionally does not refund an interrupted attempt.

`goals/<id>/goal.json` is authoritative. Atomic replacement and revision comparisons happen under an exclusive workspace write lock. `log.md` is append-only and `GOAL.md` is generated. A crash after JSON commit can leave stale projections, repaired on the next read. A crash while holding `.write-lock` fails closed; after confirming every writing host is stopped, an administrator can remove that stale lock before reopening. Keep Goals state off unrestricted same-user filesystem access for agent sessions: path validation and actor-bound tool authorization do not sandbox arbitrary local shell processes. The native Goals backend does not claim that unrestricted Execute sessions are a security boundary.

## SessionManager integration

`SessionManager` starts `startGoalHost()` after loading session metadata and stops it on cleanup. Startup blocks interrupted goals rather than launching them. The host checks eligible local workspaces once per minute (at most ten due goals per workspace per pass, no overlapping passes); remote workspaces are owned by their own host. A wake is recorded as admitted only after the message is durably admitted to an idle session. Busy sessions block instead of queueing goal work. Pausing or stopping aborts pending admission, hard-stops the linked sessions and their known descendants, and cancels retries tracked by SessionManager.

New scheduled owner and verifier sessions start idle in Execute mode, without inherited projects or sources. If a workspace requires a lower startup mode or a linked session changes modes, the scheduler refuses the wake. Explore still blocks Goal mutations. `GOAL_OWNER_TOOL_ACCESS` defaults to `goal-only`: linked sessions can read their own `GOAL.md` and evidence and call assigned Goal tools. They cannot run shell commands, edit projects or use connected sources. The verifier is always restricted. These checks cover the supported Claude/Pi paths, not arbitrary same-user filesystem access or an OS sandbox. No wake runs while the app/server is closed. An admitted turn is not proof of completion; only the independent verifier can record that result.
